# 8주차 — 병목 분석과 최종 과제

[전체 로드맵](../../README.md#주차별-로드맵) · [← 7주차](week07.md)

**구현 목표:** 측정 가능한 가설을 세워 특정 shape군을 개선하고 결과를 보고합니다.

## 구현 과제

1. 작은 M, 큰 정방형, 긴 K 등 목표 shape군 하나와 비교용 shape군을 정합니다.
2. 기존 커널을 baseline으로 고정하고, 연산 처리량·메모리 대역폭·occupancy·launch 비용 중 병목 후보를 프로파일링으로 좁힙니다.
3. tile, stage, layout, epilogue 중 효과를 설명할 수 있는 변수를 바꿉니다. 최소 세 가지 후보와 baseline을 비교합니다.
4. 튜닝에 직접 사용하지 않은 shape에서도 검증하고, 성능이 악화되거나 개선되지 않은 결과도 보존합니다.

## 선택 확장 과제

기본 튜닝 과제 대신 아래 과제 하나를 선택할 수 있습니다. 선택한 과제의 추가 완료 기준만 체크합니다.

### Strided batched GEMM

같은 shape의 여러 GEMM을 batch로 처리합니다.

- [ ] 개별 launch 및 cuBLAS batched 실행과 정확성·전체 시간을 비교했다.

### Grouped GEMM

서로 다른 shape의 GEMM들을 묶어 실행합니다.

- [ ] shape 분포별 스케줄링 효과와 전체 시간을 분석했다.

### 추가 epilogue 융합

Bias+GELU 또는 residual add를 융합합니다.

- [ ] 수식·근사 방식을 명시하고, 분리 구현과 정확성·시간을 비교했다.

## 산출물 및 완료 기준

- [ ] 기본 튜닝 또는 확장 과제 하나를 선택하고 목표 shape군과 비교용 shape군을 기록했다.
- [ ] baseline을 고정하고 프로파일링으로 병목 가설을 세웠다.
- [ ] 최소 세 가지 후보와 baseline의 정확성·성능을 비교했다.
- [ ] 튜닝에 사용하지 않은 shape를 검증하고 개선되지 않거나 악화된 결과도 보존했다.
- [ ] 환경, 문제 정의, 가설, 변경 내용, 검증 방법, 성능 표/그래프, 해석, 한계를 담은 2~4쪽 보고서를 작성했다.
- [ ] 소스 코드, 빌드·실행 명령, 검증 로그와 해당 주차의 결과·해석을 남겼다.

검증과 측정은 [공통 규칙](../../README.md#공통-검증-및-측정-규칙)을 따릅니다. 완료한 항목은 `- [ ]`를 `- [x]`로 바꿉니다.
